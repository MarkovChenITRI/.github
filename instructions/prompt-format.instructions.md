# Prompt 文件架構規範

每個 prompt 文件是一份執行 SOP，讓 Copilot 在使用者以 `/名稱` 觸發或自然語言描述需求時，能夠依序完成一件有邊界的任務並輸出到指定路徑。文件結構固定五個部分，依序出現：Frontmatter、H1 標題與定位段落、開始之前、主動作段落、寫入、完成條件。

## Frontmatter

必填一個欄位：

```yaml
---
description: "<觸發語境>"
---
```

`description` 從使用者的角度描述觸發情境，不是 SOP 內部的步驟說明。格式固定為：「動詞 + 受詞 + 產出路徑」，例如「從 0 或局部協助使用者為一個新模組撰寫規格，寫入 `<專案資料夾>/.github/specs/<layer>/<module>.md`」。不出現 Copilot 的內部步驟細節。

## H1 標題與定位段落

```markdown
# <職責名稱>

<定位段落>
```

H1 是這份 SOP 的職責名稱，不含「SOP」字樣。定位段落緊跟 H1，一到兩句，固定交代三件事：

1. 這個 SOP 的職責邊界（做什麼、不做什麼）
2. 主要依循哪份 format instructions 的哪個段落
3. 產出物的路徑格式

範例：「依 `.github/instructions/spec-format.instructions.md` 的「模組規格」格式，透過問答協助使用者建立一個模組的規格；實際執行與記錄測試結果交給 `test` 技能，不在這裡處理。產出寫入 `<專案資料夾>/.github/specs/<layer>/<module>.md`。」

## 開始之前

這段列出進入主動作前必須確認的前提條件，固定編號清單，依序涵蓋三項：

1. **確認目標名稱或範圍**：使用者未提供時，先詢問，確認後才繼續。
2. **確認目標檔案是否已存在**：
   - 已存在且本次要處理的段落有內容：告知使用者已存在，詢問要整組重新建立、還是局部更新；使用者選定後才繼續。
   - 不存在，或本次要處理的段落還沒內容：繼續下方主動作段落。
3. **確認相依的前置資源**：例如 overview.md 是否存在、目錄結構是否已選定、相依的上游文件是否齊備。相依資源不存在時，停下來說明原因，不進入主動作段落。

三項都確認完才進入主動作段落。

## 主動作段落

這段是 SOP 的核心步驟，段落名稱依職責類型選擇，不任意自訂：

| 職責類型 | 段落名稱 |
|---|---|
| 透過問答收斂內容（最常見） | `## 問答步驟` |
| 親自操作系統並記錄結果 | `## 執行步驟` |
| 需分階段研究後定案（複雜型） | `## 第一階段：<名稱>` + `## 第二階段：<名稱>` |

**問答步驟**的內部規則：每個欄位或段落問完，先覆誦使用者的回答確認理解正確，再問下一個；有順序依賴的欄位（後者的格式依賴前者的結果），必須說明依賴關係，不能同時問。

**執行步驟**的內部規則：依步驟表逐步操作，每一步記下實際觀察到的結果，包含與預期不符的步驟；不跳步驟。

**多階段研究**的內部規則：每個階段用獨立的 H2 段落；第一階段結束時必須讓使用者確認才進入第二階段；最後一個階段結束後才進入「寫入」段落。

## 寫入 \<目標文件種類\>

這段固定三個子步驟，不增減：

1. 依 `<format-instructions>.md`「<段落名稱>」的格式，把問答或執行得到的內容整理成可寫入的狀態。
2. 開啟 `<專案資料夾>/<路徑>/<檔名>.md`，把整理好的內容寫入；檔案不存在時先建立。
3. 在對話中貼出寫入的完整內容，請使用者確認。

**段落名稱規則**：固定是「寫入 + 目標文件種類」，目標文件種類取自這份 SOP 的產出對象，例如：

- 寫入規格書（模組規格）
- 寫入系統架構（overview.md）
- 寫入計劃書（proposal 的各段落）
- 寫入驗收標準（usage-examples）
- 寫入測試紀錄（operations 執行紀錄）

「在對話中貼出內容請使用者確認」不能挪到完成條件——確認是寫入步驟的一部分，不是結束後才做的收尾。

## 完成條件

可查核的清單，依序涵蓋三類，缺一不可：

1. **格式面**：目標檔案路徑存在、必填段落齊全——逐一對照所依循的 format instructions 範本欄位確認。
2. **內容面**：具體性要求（例如「每個模組與跨層引用關係都有具體到可判斷的描述」）與一致性要求（例如「三段用的分項子項名稱互相一致」）；如果這份 SOP 的產出和其他文件有名稱或時間上的對應關係，也在這裡列出一致性查核。
3. **程序面**：固定以「使用者已確認過寫入的內容」這一條作為最後一項。

## 對照現有 prompt 文件的落差

寫新 prompt 文件時依上方架構；更新現有 prompt 文件時，先對照下列落差清單補齊：

| 文件 | 落差項目 |
|---|---|
| `plan-overview.prompt.md` | 定位段落未交代依循哪份 format instructions；完成條件缺「使用者已確認」一條 |
| `plan-module-spec.prompt.md` | 「寫入規格書」段落的三個子步驟格式符合；完成條件缺格式面查核 |
| `plan-usage-example.prompt.md` | 寫入段落名稱為「寫入初稿」，應改為「寫入驗收標準」；完成條件缺格式面查核 |
| `plan-proposal-narrative.prompt.md` | 開始之前第 2 項分支說明缺「告知使用者已存在」的明確動作 |
| `plan-proposal-schedule.prompt.md` | 開始之前第 2 項分支說明缺「告知使用者已存在」的明確動作 |
| `operations-test.prompt.md` | 缺「寫入測試紀錄」段落（目前把寫入動作埋在完成條件第 2 條，讀執行時會遺漏） |
