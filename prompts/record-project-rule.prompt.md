# 專案特有規則的記錄 SOP

## 開始之前

1. 整理這次確立的規則：規則的具體內容、適用的檔案或路徑範圍。

## 提案與確認

1. 把整理好的規則內容，用一句話覆誦給使用者看，說明打算寫進哪個檔案。
2. 使用者確認要記錄，才進入下一步；使用者說不用記、或要修改內容，依使用者的回應調整或中止，不寫入檔案。

## 寫入步驟

1. 判斷要寫入的專案：以這次確立規則時正在異動或討論的檔案為準，往上找到最近的 `.git` 倉庫根目錄，這個倉庫的資料夾就是要寫入的專案，跟這個共用 `.github` 倉庫是不同的倉庫。
2. 把這個規則寫進這個專案資料夾底下的 `.github/instructions/<name>.instructions.md`：frontmatter 寫 `description`（這個規則是什麼、何時該用）與 `applyTo`（涵蓋的檔案路徑 glob）。
3. 這個路徑第一次在這個專案裡出現時，開啟共用工作區（workspace）設定——也就是跟這個共用 `.github` 同一層工作目錄底下的 `.vscode/settings.json`——裡的 `chat.instructionsFilesLocations`，用絕對路徑把這個資料夾加進去；清單裡對應資料夾已經不存在的舊登記，一併清除。
4. 寫回後，依 `.github/copilot-instructions.md` 的「修改後要重新讀取確認」規定，重新開啟寫入的檔案，逐項比對內容是否相符。

## 完成條件

1. 使用者已經確認過規則內容。
2. 專案自己的 instructions 檔案已經寫入，內容跟提案時一致。
3. 這個檔案的路徑已經登記在共用工作區設定裡。
4. 在對話中告知使用者這次記錄的結果。
